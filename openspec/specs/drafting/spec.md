# drafting Specification

## Purpose

The default `Qualified -> Queued` step: generate a personalized first-touch message for a qualified prospect from the user profile and the signal, through the LLM port, persist it as the selected draft, and move the prospect into the review queue. Drafts are regenerable (a re-draft archives the prior selected, one selected per prospect); a below-bar prospect is never drafted; every draft records its provider/prompt/model for evals. Grounding a richer re-draft in a dossier is the enrichment capability's extension (ADR-0007).

## Architecture

- Decisions: [ADR-0007](../../../docs/adr/0007-user-triggered-optional-enrichment.md) (default draft-from-signal; enrichment optional), [ADR-0008](../../../docs/adr/0008-prospect-status-is-disposition.md) (sets the `queued` disposition; "drafted" is derived from the DRAFT relation, not a status), [ADR-0003](../../../docs/adr/0003-llm-provider-port.md)/D9 (LLM via the port), D5 (draft is a separate call from qualify). Pipeline: [product-overview.md](../../../docs/product-overview.md) section 4.
- Data model: `DRAFT` (one `selected` per prospect, regenerable) in [domain-model.md](../../../docs/architecture/domain-model.md).
- Reuses the `LLMProvider` port (`src/lib/llm`, fake injected in tests), the user profile config-as-data (`src/lib/icp`, `getUserProfile`), and qualification's worker - the enqueue-on-qualify hook is wired at the composition root so qualification never imports drafting. Surfaced in the review-queue and prospect-list anchor views (the "Regenerate" affordance maps to a forced re-draft); see the [prototype registry](../../../src/app/prototype/README.md).

## Requirements
### Requirement: A qualified prospect is drafted a personalized first touch

The system SHALL generate a personalized first-touch message for a qualified prospect from the user profile (positioning, offer, voice, case studies) and the prospect's signal, through the LLM port, and persist it as a draft. A below-bar prospect SHALL NOT be drafted. (Grounding a re-draft in a richer dossier when a prospect is enriched is owned by the enrichment capability, per ADR-0007; drafting delivers the default signal-grounded first touch.)

#### Scenario: A qualified prospect is drafted

- **WHEN** a prospect is qualified
- **THEN** a first-touch message is generated for it from the user profile and the signal, and persisted as a draft

#### Scenario: A below-bar prospect is not drafted

- **WHEN** a prospect is below the bar
- **THEN** no draft is generated for it

### Requirement: Drafting moves the prospect into the review queue

The system SHALL move a prospect to the queued disposition once a draft exists for it, so it appears in the review/approve queue for the human. The draft itself SHALL never be sent automatically - sending is always a human action.

#### Scenario: A drafted prospect is queued

- **WHEN** a draft is persisted for a prospect
- **THEN** the prospect's status becomes queued and it is available for human review

### Requirement: Drafts are regenerable with one selected at a time

The system SHALL allow a prospect to accumulate multiple drafts over time (for example, a richer re-draft after enrichment), with exactly one marked selected as the current candidate; generating a new draft SHALL select it and archive the previously selected one rather than overwrite it.

#### Scenario: A re-draft supersedes the prior selected draft

- **WHEN** a new draft is generated for a prospect that already has a selected draft
- **THEN** the new draft becomes selected and the previous one is archived, both retained

### Requirement: Drafting is idempotent and traceable

The system SHALL NOT auto-generate a second draft for a prospect that was already drafted by the automatic draft-on-qualify path, even if requested more than once or concurrently. Every draft SHALL record the provider, model, and prompt version that produced it for evaluation.

#### Scenario: Auto-draft does not double-draft

- **WHEN** the automatic draft step runs more than once for the same just-qualified prospect
- **THEN** only one draft is generated by that path

#### Scenario: A draft carries its provider, model, and prompt version

- **WHEN** a draft is generated
- **THEN** the recorded draft includes the provider, model, and prompt version used
