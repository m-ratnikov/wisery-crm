No system boundary, container, or external-system change. Manual lead entry is a new web action inside the existing **Wisery CRM app** container - the prospect-list anchor view plus a Server Action - that creates a `Prospect` and enqueues qualify fire-and-forget (a user-triggered enqueue per ADR-0009, not the atomic in-transaction handoff reserved for pipeline stage-to-stage handoffs). It introduces no new container, no external system, no new protocol, and no new outbound edge.

The new runtime flow - a `Prospect` created without a `Scan`/`Signal`, then qualified by `prospectId` - is captured in [domain-model.md](domain-model.md) (the `ProspectAddedManually` event, the second entry into `New`, and the "Consumer impact" note). From the qualify stage onward a manual-origin prospect is indistinguishable in the existing intelligence-pipeline flow in `docs/architecture/system-design.md`. This view is Skip because nothing at the container (C4 L2) altitude changes; but to be clear this is not a no-op at the component (L3) altitude: the implementing code change introduces a `PersonIdentity` read seam replacing the scorer/drafter/`loadActionableProspect` direct `SignalRow` dependency, a prospect-keyed qualify entry, left-joined prospect read-models, and a re-qualify action (see domain-model.md "Consumer impact"). Those are component-level seams owned by that code change, below this view's altitude, not new containers or boundaries.

In-force ADRs are honored unchanged: ADR-0001 (in-process worker runtime), ADR-0009 (manual add is a user-triggered enqueue and so is fire-and-forget, exactly the carve-out ADR-0009 names for manual/batch enrich and regenerate-draft - it is not the atomic in-transaction handoff reserved for pipeline stage-to-stage handoffs). The only ADR this change touches is the new ADR-0010 (see adr/), which supersedes ADR-0005's cardinality decision; that is a data-model decision, not a structural/container one, which is why this view is Skip.
